# Widget plugin

A Widget plugin contributes dockable panels. Each panel shows a Qt widget the
plugin creates; the user wires series to the widget's named inputs in the host.
The host owns the data and the layout, the plugin owns the pixels. A widget only
consumes: it creates no series and no datasets.

Full reference: `pj_plugins/docs/widget-guide.md`. Working example without Qt:
`pj_plugins/widget_protocol/examples/mock_widget.cpp`.

## Header + skeleton

```cpp
#include <QPointer>
#include <QtWidgets/QLabel>
#include <pj_plugins/sdk/widget_plugin_base.hpp>

#include "my_manifest.hpp"   // kMyManifest, generated by pj_configure_plugin

class Battery : public PJ::WidgetPluginBase {
 public:
  std::vector<PJ::WidgetInput> inputs() const override {
    return {PJ::WidgetInput("voltage", "Voltage", "V")};   // name, label, unit
  }
  void* createWidget(void* parent) override {
    label_ = new QLabel(static_cast<QWidget*>(parent));
    return label_.data();
  }
  void onUpdate(PJ::Span<const PJ_widget_value_t> values, double /*time*/) override {
    for (const PJ_widget_value_t& v : values) {   // one entry per wire: dispatch on v.input
      if (v.input == 0 && label_) {
        label_->setText(v.kind == PJ_WIDGET_VALUE_NUMBER ? QString::number(v.number, 'f', 1) : QString("-"));
      }
    }
  }

 private:
  QPointer<QLabel> label_;   // the widget may already be gone when the plugin is destroyed
};

PJ_WIDGET_PLUGIN(Battery, kMyManifest)
```

One library can offer several widget types: give the class a constructor taking
`std::string_view type` and throw `std::invalid_argument` for an unknown one.

## Build and manifest

```cmake
find_package(Qt6 REQUIRED COMPONENTS Widgets)
add_library(my_widgets SHARED battery.cpp)
target_link_libraries(my_widgets PRIVATE plotjuggler_sdk::plugin_sdk Qt6::Widgets)
pj_configure_plugin(my_widgets FAMILIES widget
  MANIFEST_FILE ${CMAKE_CURRENT_SOURCE_DIR}/manifest.json
  MANIFEST_HEADER generated/my_manifest.hpp MANIFEST_VAR kMyManifest)
```

```json
{
  "id": "my-widgets", "name": "My Widgets", "version": "1.0.0",
  "min_sdk_required": "0.39.0",
  "qt_modules": ["Core", "Gui", "Widgets"],
  "widgets": [
    { "type": "battery", "name": "Battery", "icon": "<svg ...>...</svg>",
      "settings": [ { "key": "min", "type": "number", "default": 0, "label": "Minimum" } ] }
  ]
}
```

- `widgets` is required and non-empty. `type` is permanent (layouts store
  `plugin_id/type`) and must not contain `/`; `name` and `icon` may change.
- `qt_modules` lists the Qt modules the library links, taken only from
  `pj_plugins/widget_qt_modules.h` (installed as
  `share/plotjuggler_sdk/widget_qt_modules.json`).
- `min_sdk_required` is at least `0.39.0`, the release that introduced the family.
- `settings` is a declarative form the host draws and stores. The plugin has no
  settings UI: it receives the values through `loadConfig(json)`.

## Inputs, values, history

- **`inputs()`** returns `PJ::WidgetInput{name, label, unit, kind, multiple}`.
  `name` is the identity the host matches wires by: non-empty, unique, stable.
  `kind` is `kNumber`, `kText` or `kObject` (bytes to decode with the `pj_base`
  codecs). `multiple = true` only where every wired series is treated alike (a
  table of values). The list may depend on settings; call
  `widgetHost().notifyInputsChanged()` when it changes.
- **`onUpdate(values, time)`** carries one value per *wire*: an unwired input has
  no entry, a `multiple` input has one per series (`slot`). `time` is in seconds
  on the host's display axis. The host also calls it with no changed sample
  (after `createWidget`, an accepted `loadConfig`, a wiring change), so treat
  every call as "re-read what you need", then repaint.
- **History is requested, not pushed:**
  `widgetHost().queryHistory(input, slot, from, to, max_samples, callback)` calls
  back once per sample and returns the count the range held before the host's
  cap or decimation.
- **Configuration:** `loadConfig(json)` receives every key declared in
  `settings` (the host fills in the manifest defaults) with whatever
  `saveConfig()` last returned laid over it. Do not reuse a setting key for
  internal state.
- **Playback:** the optional `pj.playback.v1` service in the registry passed to
  `bind` reads the play state and seeks. Treat it as absent until the lookup succeeds.

## Traps specific to Widget

- **Own library, own Qt.** Widget is the only family that links Qt. Never put
  another family in the same library, and never link Qt from another family.
- **Same Qt major.minor as the host.** `PJ_WIDGET_PLUGIN` records the Qt version
  it was compiled with from `QT_VERSION_*`, so the translation unit that expands
  it must include a Qt header. The host refuses a mismatch. No Qt private
  headers and no QRhi: they tie the plugin to one exact Qt.
- **Destruction is synchronous.** The host calls `setParent(nullptr)`, then
  destroys the instance, whose destructor deletes the widget if it is still
  alive. Hold the widget in a `QPointer` and never call `deleteLater` on it.
- **Main thread only.** Do not start a thread that touches the widget or the host.
- **Values are borrowed.** Every pointer in a `PJ_widget_value_t` (`text`,
  `bytes`, `type_name`, `label`) is valid only during the call: copy what you keep.
- **Never read data in `paintEvent`.** Keep your own copy from `onUpdate` or
  `queryHistory`; the host may refuse a history query from a paint handler.
- **Dispatch on `v.input` and `v.slot`**, never on the position in `values`.
- **Report an `inputs()` failure by throwing.** The host then keeps the inputs
  and wires it had, instead of reading the failure as "no inputs".
- **Linux: build on Ubuntu 22.04**, since a library built with a newer libstdc++
  fails to load in the official host. **Windows: MSVC**, and release and debug
  runtimes do not mix.

## Testing

`pj_plugins/sdk/testing/fake_widget_host.hpp` (`PJ::sdk::testing::FakeWidgetHost`)
is an in-memory `pj.widget_host.v1` host: feed samples per wire, drive
`on_update` at a tracker time, and assert on history queries, caps and
decimation without a running host.
